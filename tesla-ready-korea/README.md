주차장에 들어서면 테슬라 공조가 알아서 켜집니다. 주차장은 여러 곳을 등록할 수 있습니다. 일정이 있는 날에는 실시간 교통을 보고 출발 시간에 맞춰 공조를 켜고, 목적지 건물 주차장을 차량 내비로 보내 줍니다.

## 어떻게 동작하나요

```
[폰 Tesla Ready app / MacroDroid / 아이폰 단축어] 주차장 진입
   → HTTP POST (웹훅)
   → [Grok Bot 루틴] 평일 퇴근 시간대인지, 오늘 이미 켰는지 확인
   → [작업용 컴퓨터] 토큰 갱신 → 명령 서명 프록시
   → [Tesla Fleet API] 차량 깨우기 → 공조 켜기 → 켜졌는지 확인
```

일정 기반 준비일 때는 공조를 켜면서 일정 장소를 차량 내비 목적지로 함께 보냅니다 (아래 5절). 주차장 웹훅 퇴근 공조는 목적지가 없어 보내지 않습니다.

- 실제 기록: 신호를 보내고 1분 안에 공조가 켜졌습니다.
- 공조는 하루에 한 번만 켭니다. 정해 둔 시간대 밖이면 무시합니다.
- 공식 API만 씁니다 (Tessie, TeslaFi 같은 서드파티는 안 씀). 서드파티는 월 구독료가 있고 Tesla 계정 토큰을 외부 회사에 맡겨야 합니다. 공식 API를 쓰면 비용은 사실상 0원이고, 키와 토큰이 내 봇 컴퓨터에만 있습니다.

## 🔰 API가 처음이라면

난이도는 중상입니다. 다만 어려운 기술 작업 대부분은 Grok Bot이 자기 컴퓨터에서 대신 해 줍니다. 템플릿을 가져온 뒤 봇에게 "처음부터 같이 해 줘"라고 하면 됩니다.

**봇이 해 주는 일**
- 키 쌍(개인키·공개키) 만들기
- `tesla-http-proxy` 설치와 실행
- 토큰 갱신, 차량 깨우기, 공조 켜기 스크립트 만들기
- 파트너 등록 요청 보내기, 웹훅 루틴 만들기
- 테스트 결과 확인과 오류 원인 찾기

**내가 직접 해야 하는 일** (화면 클릭 위주)
1. GitHub 가입 → 새 저장소 `<아이디>.github.io` 만들기 → Pages 켜기
2. 봇이 준 공개키 파일을 저장소의 `.well-known/appspecific/` 폴더에 올리기 (봇이 파일과 경로를 알려 줌)
3. developer.tesla.com 로그인 → 앱 만들기 → 봇이 알려 주는 origin, 리디렉트 URL, 권한 입력
4. Client ID는 봇에게 알려 주고, Client Secret은 봇이 띄우는 비밀값 입력 카드에만 넣기 (채팅에 붙여 넣지 않기)
5. 봇이 준 인증 링크를 열어 Tesla 계정으로 승인
6. Tesla 앱이나 차량 화면에서 가상 키 승인
7. 결제 페이지에서 결제수단 확인
8. 폰 자동화 만들기: 안드로이드 MacroDroid 매크로 또는 아이폰 단축어 개인 자동화 (4번 항목대로)

막히면 그 화면을 캡처해서 봇에게 보내면 됩니다. 아래 1~3번은 봇이 무엇을 하는지 궁금한 분을 위한 상세 설명입니다.

## 1. Tesla Fleet API 앱 만들기

1. developer.tesla.com에서 앱을 만듭니다. 앱 이름에 `tesla`나 한글이 들어가면 거부됩니다.
2. EC 키 쌍을 만들고, 공개키를 GitHub Pages의 `/.well-known/appspecific/com.tesla.3p.public-key.pem`에 올립니다. 개인키는 작업용 컴퓨터에만 둡니다.
3. 허용 origin(`https://<아이디>.github.io`)과 리디렉트 URL(`.../callback`)을 등록합니다.
4. 파트너 계정을 등록합니다. 한국 차량도 NA 엔드포인트(`fleet-api.prd.na.vn.cloud.tesla.com`)를 씁니다.
5. OAuth 권한(scope): `openid offline_access vehicle_device_data vehicle_cmds vehicle_charging_cmds vehicle_location`
   vehicle_location을 빼먹으면 나중에 다시 인증해야 합니다.
6. 차량 화면이나 Tesla 앱에서 가상 키(서드파티 키)를 승인합니다.

💰 요금: 명령 1,000건당 $1, 데이터 500건당 $1, 깨우기 50건당 $1이고, 매달 $10 할인이 있습니다. 개인이 쓰는 양이면 사실상 0원입니다 (추정). 결제수단이 없으면 앱이 비활성화될 수 있으니 결제 페이지를 한 번 확인하세요.

## 2. 명령 서명 프록시와 스크립트

최신 테슬라는 서명된 명령만 받습니다.

- Tesla 공식 `vehicle-command`의 `tesla-http-proxy`를 `127.0.0.1:4443`에 띄웁니다.
- 스크립트가 하는 일은 다음 순서입니다.
  1. 프록시가 꺼져 있으면 띄웁니다 (재부팅 대비).
  2. refresh token으로 토큰을 갱신합니다.
  3. `wake_up`을 보냅니다. 본문 `{}`와 `Content-Type: application/json`이 꼭 있어야 합니다 (빈 본문이면 406).
  4. 차량이 online이 될 때까지 최대 약 1분 기다립니다.
  5. 프록시로 `auto_conditioning_start`를 보냅니다.
  6. `climate_state`로 켜졌는지 확인합니다.
- 상태 파일에 `last_on_date`를 남겨 하루 한 번만 켜지게 합니다.

## 3. Grok Bot 웹훅 루틴

- 트리거: 웹훅
- 본문에 `test`가 있으면 받았다는 확인만 보냅니다.
- 본문으로 신호를 구분합니다: `parking_enter`는 퇴근 공조(Tesla Ready app은 `{"event":"parking_enter","place":"<장소 이름>"}`처럼 장소 이름을 함께 보냄. `place`가 있으면 보고에 적고, 없어도 똑같이 처리. 같은 장소에서 10분 안에 다시 온 신호는 무시), `after_blow`는 애프터 블로우(6절, 켠 경우만).
- 그 외에는 평일 17:30~23:00(원하는 시간으로 바꾸면 됨)이고 오늘 아직 안 켰으면 스크립트를 실행합니다. 실패하면 한 번 다시 시도합니다.
- 루틴 패널에 웹훅 URL과 키가 나옵니다. Grok Bot 폰 앱으로 구축하고 있다면, URL과 키는 지금 PC에서만 보이니 PC에서 복사해 폰으로 옮기세요. 옮길 때 쓴 사본(메신저, 메일 등)은 지우세요.

## 4. 폰 자동화 (안드로이드 Tesla Ready app 권장 · MacroDroid 대안 / 아이폰 단축어)

### 안드로이드: Tesla Ready app (권장)

이 가이드용으로 만든 안드로이드 앱입니다. 매크로를 직접 만들 필요 없이 웹훅 URL·키를 넣고 주차장만 고르면 됩니다. 실제 퇴근길에서 주차장 진입 → 공조 켜짐까지 한 번 확인했습니다.

- 다운로드: [Tesla Ready app v1.0.4 APK](https://github.com/Fnel-second/tesla-ready-app-releases/releases/latest/download/TeslaReadyApp.apk) (Android 8.0 이상). 업데이트는 새 APK를 지금 앱 위에 설치하면 됩니다(설정 유지).
- 앱은 입력한 웹훅 주소 한 곳과만 통신하고, 웹훅 URL·키는 폰 안에 암호화해 저장합니다.

**설치 (순서대로)**
1. **출처를 알 수 없는 앱 허용**: APK를 연 브라우저나 '내 파일' 앱에 설치 권한을 허용합니다.
2. **Play 프로텍트 경고**: 「기기 보호를 위해 앱 차단됨」 화면이 뜨면 **「확인」을 누르지 마세요**(설치가 취소됨). 「세부정보 더보기」를 펼친 뒤 「무시하고 설치」를 누릅니다.
3. **위치 권한 '항상 허용'**: 앱 안내에 따라 위치를 '항상 허용'으로 바꿉니다. "제한된 설정" 때문에 막히면 설정 > 애플리케이션 > Tesla Ready app > 오른쪽 위 ⋮ > '제한된 설정 허용' 후 다시 시도합니다(메뉴 위치는 제조사마다 다를 수 있음, 추측).
4. **배터리 최적화 제외**: 설정에서 Tesla Ready app을 배터리 최적화 '제한 없음'(제외)으로 둡니다. 안 하면 지오펜스가 늦거나 안 울릴 수 있습니다.
5. **알림 허용**: 전송 결과와 취소 알림을 보려면 필요합니다.

**설정**
1. **웹훅**: 3절 루틴 패널의 웹훅 URL과 키를 입력합니다. 키 칸은 가려지고 저장 뒤 앞 4자만 보입니다.
2. **주차장 저장 (여러 곳 가능)**: 지도에서 핀을 찍고 반경 원을 슬라이더로 정합니다(100~1000m, 기본 300m). 장소마다 이름과 켜기/끄기가 있습니다. 지도 없이 지금 서 있는 곳을 쓰려면 「지금 위치를 주차장으로 저장」을 누릅니다.
   - 지도: 네이버 지도 Client ID(본인 것, 선택)를 넣으면 네이버 지도, 없거나 인증이 실패하면 OpenStreetMap으로 보입니다.
   - 네이버 지도 Client ID 받기: NCP 콘솔 → Maps → Application 등록 → `Dynamic Map` 선택 → Android 패키지 이름 `app.teslaready.android` 입력. 길찾기·검색 비밀 키는 앱에 넣지 않습니다(봇 쪽에서만 씀). 같은 패키지 이름을 여러 NCP 계정에 등록할 수 있는지는 확인되지 않음.
3. **테스트**: 「테스트 전송」 버튼 → `{"event":"test"}`가 가고 봇에서 확인 메시지만 옵니다(공조는 켜지지 않음). 앱 기록에 성공이 남는지 봅니다.

**앱이 보내는 신호** (헤더 `Authorization: Bearer <웹훅 키>`, `Content-Type: application/json`)

| 상황 | 본문 |
|---|---|
| 주차장 진입 | `{"event":"parking_enter","place":"<장소 이름>"}` (같은 장소 10분 안 재진입은 앱에서도 무시) |
| 테스트 버튼 | `{"event":"test"}` |
| 차량 블루투스 끊김 (애프터 블로우, 6절) | `{"event":"after_blow"}` |
| 취소 알림·위젯·바로가기 | `{"event":"after_blow_cancel"}` |

- 애프터 블로우를 안 쓰면 앱 설정에서 차량 블루투스를 비워 두세요.
- 예전에 MacroDroid나 Automate로 주차장 신호를 보내던 분은 앱 테스트가 끝나면 그 매크로·흐름을 끄세요(신호 중복 방지).

### 안드로이드: MacroDroid (대안) / 아이폰 단축어

| 항목 | 안드로이드 (MacroDroid) | 아이폰 (단축어) |
|---|---|---|
| 만드는 곳 | 매크로 추가 (아래 단계별 설명) | 단축어 앱 > 자동화 > 개인 자동화 |
| 주차장 진입 트리거 | `Location Trigger`(위치 트리거, 지오펜스) 주차장 구역 진입 | '도착' (위치: 주차장, 반경 설정) |
| 자동 실행 | 매크로를 켜 두면 바로 실행 | '즉시 실행' 켜고 '실행 시 알림' 선택 ¹ |
| 웹훅 동작 | `HTTP Request`(HTTP 요청) | 'URL의 콘텐츠 가져오기' |
| 메서드 / URL | `POST`, `<웹훅 URL>` | 방식 `POST`, URL `<웹훅 URL>` |
| 헤더 | `Authorization` = `Bearer <웹훅 키>` | `Authorization` = `Bearer <웹훅 키>` |
| 본문 | 콘텐츠 유형 `application/json`, 본문 `{"event":"parking_enter"}` | 요청 본문 '텍스트' `parking_enter` (텍스트가 없으면 JSON `event` = `parking_enter`) ¹ |
| 권한 | MacroDroid 위치 권한 '항상 허용', 배터리 최적화 제외 | 설정 > 개인 정보 보호 > 위치 서비스 > 단축어 '항상' ¹ |
| 결과 확인 | 응답 코드를 지역 변수 `code`에 저장 → 토스트 `{lv=code}` | 다음 동작 '알림 보기'로 결과 표시 ¹ |

¹ iOS 버전마다 메뉴 이름이 다를 수 있음. 아이폰 방식은 직접 테스트하지 않았습니다.

### 안드로이드 MacroDroid 단계별 설정 (대안)

Tesla Ready app을 못 쓰거나 원하지 않을 때의 방법입니다.

메뉴 이름은 영어 화면 기준이고, 한국어 화면에서는 괄호 안 이름과 다를 수 있습니다(한국어 이름은 확인되지 않음).

1. **새 매크로**: MacroDroid → `Add Macro`(매크로 추가). 이름은 예: `퇴근 공조`.
2. **트리거**: `+` → `Location`(위치) 분류 → `Location Trigger`(위치 트리거) → `Area Entered`(구역 진입) → 지도에서 주차장을 고르고 반경을 정합니다 (예: 150m). 처음 쓰면 새 구역(geofence)을 만들라고 합니다. 옵션 이름은 확인되지 않음.
3. **동작**: `+` → `Connectivity`(연결) 분류 → `HTTP Request`(HTTP 요청).
   - 방식: `POST`
   - URL: 웹훅 URL
   - 헤더(Headers): 이름 `Authorization`, 값 `Bearer <웹훅 키>`
   - 본문(Body): 콘텐츠 유형 `application/json`, 내용 `{"event":"parking_enter"}`. 콘텐츠 유형을 안 정하면 415 오류가 납니다.
   - (선택) 응답(Response)에서 HTTP 응답 코드를 지역 변수 `code`에 저장하고, 다음 동작 `Display Toast`(토스트 표시)로 `{lv=code}`를 띄우면 결과를 볼 수 있습니다.
4. **저장**하고 매크로가 켜져 있는지(토글) 확인합니다.
5. **권한**: MacroDroid 위치 권한은 **항상 허용**(백그라운드 위치), 안드로이드 설정에서 MacroDroid **배터리 최적화 제외**.
6. **테스트**: 같은 `HTTP Request` 동작을 넣고 본문만 `{"event":"test"}`로 바꾼 테스트용 매크로를 만들어 직접 실행(Test Macro)합니다. 확인 메시지만 오고 공조는 켜지지 않습니다. 확인이 끝나면 테스트용 매크로는 지우세요.
- 무료 버전은 매크로 개수 제한이 있습니다(5개로 알려져 있음, 확인되지 않음). 이 가이드는 주차장·애프터 블로우·취소 3개만 씁니다.
- 예전에 Automate로 옮겼다면 Automate 흐름은 멈추세요. 둘 다 켜 두면 신호가 두 번 갈 수 있습니다(하루 한 번만 켜지므로 공조가 두 번 켜지지는 않음).

- (선택) 같은 자동화에서 메일도 보내 두면 백업 신호로 쓸 수 있습니다. 다만 메일 확인은 5분 간격이라 느립니다.

### HTTP 요청이 어렵다면 (Gmail 방식)

웹훅 설정이 부담스러우면 메일로 신호를 보내는 방법도 있습니다. 대신 Grok Bot이 5분마다 메일을 확인하기 때문에 최대 5분 늦게 켜집니다.

1. 폰 자동화의 동작을 메일 보내기로 바꿉니다 (받는 사람: 내 Gmail 주소, 제목: `[테슬라] parking_enter`).
   - 안드로이드: MacroDroid 동작 '이메일 보내기'(Send Email)를 HTTP 요청 대신 넣고, 받는 사람과 제목은 위와 같이 (메뉴 이름 확인되지 않음)
   - 아이폰: 단축어 동작 '메일 보내기', '보내기 전 확인'(또는 '보내기 전에 표시') 끄기 (iOS 버전마다 이름이 다를 수 있음). 끄지 못하면 자동 발송이 안 될 수 있습니다 (추측).
2. Gmail에서 필터를 만듭니다. 보낸 사람이 내 주소이고 제목에 `[테슬라]`가 들어간 메일은 받은편지함을 건너뛰고 라벨 `테슬라`를 붙이게 합니다. 받은편지함이 지저분해지지 않습니다.
3. Grok Bot에 Gmail 커넥터를 연결합니다.
4. 봇에게 "퇴근 공조 메일 루틴 만들어 줘"라고 하면 됩니다. 평일 퇴근 시간대에 5분마다 제목이 `[테슬라] parking_enter`인 새 메일을 찾고, 있으면 공조를 켜는 루틴입니다. 처리한 메일은 기록해 두어 두 번 켜지지 않게 합니다.
5. 테스트는 같은 제목으로 메일을 직접 보내 보면 됩니다.

웹훅과 메일을 같이 써도 됩니다. 하루 한 번만 켜지게 되어 있어서 먼저 도착한 신호로 켜지고, 나머지는 무시됩니다.

## 5. 일정 기반 준비 (선택)

### 📅 캘린더 연결 (권장)

Grok Bot에 Google Calendar 등 캘린더 플러그인을 연결해 두면, 봇이 일정을 직접 읽어 알아서 준비합니다.
- 일정 시작 시각 = 도착 마감 시각으로 봅니다.
- 일정의 '장소'를 목적지로 길찾기합니다. 장소 칸에 주소나 건물명을 정확히 적어 두세요.
- 연결하지 않으면 일정 기반 준비는 자동으로 돌지 않습니다. 그때는 "토요일 12:30까지 ○○ 도착" 처럼 직접 요청해야 합니다.

일정이 있는 날, 차의 실시간 위치에서 일정 장소까지의 소요시간을 네이버 Directions 15(`maps.apigw.ntruss.com`, `option=trafast`)로 구합니다.

- 차 출발 = 일정 시작 − 도착 후 여유 − 주행 시간
- 내가 출발 = 차 출발 − 걸어서 차까지 가는 시간
- 공조 켜기 = 차 출발 − 10분

출발 2시간, 1시간, 30분 전에 다시 계산해서, 길이 막히면 공조와 출발을 앞당깁니다.

### 🧭 내비 목적지 자동 전송

공조를 켜는 시점에 목적지(가능하면 그 근처 주차장)를 차량 내비로 보내 둡니다. 타자마자 바로 출발할 수 있습니다.
1. 일정(캘린더 이벤트)의 '장소'에서 목적지를 읽습니다.
2. 네이버 주소 검색(Geocoding)으로 목적지 좌표를 구합니다.
3. NAVER API HUB 지역 검색 API로 '목적지명 + 주차장'을 찾습니다.
   - `GET https://naverapihub.apigw.ntruss.com/search/v1/local?query=<목적지명 주차장>&display=5&start=1&sort=random` (display 최대 5)
   - 헤더: `X-NCP-APIGW-API-KEY-ID`, `X-NCP-APIGW-API-KEY` (환경 변수 `NAVER_SEARCH_CLIENT_ID` / `NAVER_SEARCH_CLIENT_SECRET`)
   - 결과의 `mapx`/`mapy`는 정수이며 10^7로 나누면 WGS84 경도/위도입니다 (예: 1270856213 → 127.0856213).
   - 목적지명은 일정 장소의 장소/건물 이름을 씁니다(주소 문자열 아님). 장소에 주소만 있으면 주소 검색 결과의 건물명을 쓰고, 건물명도 없으면 주차장 검색을 건너뛰고 원래 주소로 갑니다.
   - 후보 조건: 장소 이름(`title`, HTML 태그 제거·공백 무시)에 목적지명이 들어간 것만 남깁니다. 예: 목적지 'OO병원'이면 'OO병원 주차장', 'OO병원 별관 주차장'만. 근처 공영·다른 건물 주차장은 가까워도 제외합니다.
   - 500m 거리 조건은 이름 조건을 통과한 후보에서 엉뚱한 지점을 빼는 보조 필터로만 씁니다.
   - ⚠️ 네이버에 해당 이름으로 등록된 주차장이 없으면 원래 주소로 갑니다.
   - 이 검색과 선택은 공조 켤 때가 아니라 일정을 처음 받아 출발 계획을 잡을 때 미리 합니다.
     - 후보 1개: 묻지 않고 그 주차장으로 정합니다.
     - 후보 여러 개(최대 5): 이름과 주소 목록을 보여 주고 고르게 한 뒤, 선택을 기억(루틴 상태)에 저장합니다.
     - 공조 켤 때까지 답이 없으면 후보 중 목적지에서 가장 가까운 주차장으로 보내고, 그 사실을 보고에 적습니다.
     - 후보 0개(또는 키 미등록 기존 사용자): 원래 주소 좌표를 씁니다.
   - 키가 아직 등록되지 않은 기존 사용자는 이 단계 없이 2단계의 주소 좌표를 씁니다 ([업데이트 가이드](https://fnel-second.github.io/tesla-ready-korea/update.html)).
4. 서명 프록시로 `navigation_gps_request` `{"lat": <위도>, "lon": <경도>, "order": 0}`를 보냅니다. 정해 둔 주차장 좌표, 없으면 원래 주소 좌표입니다.
5. 실패하면 `share`로 주소를 보냅니다: `{"type": "share_ext_content_raw", "locale": "ko-KR", "timestamp_ms": <현재 ms>, "value": {"android.intent.extra.TEXT": "<주소>"}}`
6. 공조 보고에 결과를 넣습니다: 목적지 종류(선택한 주차장 / 무응답으로 가장 가까운 주차장 / 원래 주소)와 사용한 명령(navigation_gps_request / share / 실패).
7. 차에 타면 화면의 목적지가 맞는지 한 번 확인하세요.

> **📌 네이버 키 한눈에 보기: 같은 NCP 콘솔, 두 곳에서 각각 1쌍**
>
> | | ① Maps 키 (필수) | ② 지역 검색 키 (선택) |
> |---|---|---|
> | 어디서 | NCP 콘솔 → Services → AI·Application Service → **Maps** → Application 등록 | NCP 콘솔 → Services → Application Services → **NAVER API HUB** → Application 등록 |
> | 무엇을 체크 | **Directions 15**, **Geocoding** (한 Application에 둘 다) | **지역**(지역 검색 결과 조회, NAVER Search Local API) |
> | 받는 키 | 1쌍 → `NAVER_MAPS_CLIENT_ID` / `NAVER_MAPS_CLIENT_SECRET` | 1쌍 → `NAVER_SEARCH_CLIENT_ID` / `NAVER_SEARCH_CLIENT_SECRET` |
> | 쓰는 곳 | 길찾기(출발 시각 계산), 주소→좌표 | 목적지 주차장 찾기(내비 전송)에만 |
>
> - Maps에는 지역 검색이 없습니다. 주차장 검색은 ②에서만 됩니다.
> - developers.naver.com(네이버 개발자센터)은 검색 API 신규 신청을 더 이상 받지 않습니다. ②는 NAVER API HUB에서 받으세요.
> - 키는 채팅에 붙여 넣지 말고 봇의 비밀값 입력 카드로 넣으세요.

**지역 검색 키 받는 법 (일정 기반 준비를 쓸 때 필수)**: 네이버 개발자센터의 검색 API는 2026년 7월 31일부터 신규 신청이 막히고 NAVER API HUB로 옮겨졌습니다([공지](https://developers.naver.com/notice/article/32530)). 네이버 클라우드 플랫폼(NCP) 콘솔 → Services → Application Services → NAVER API HUB → 이용 신청 → Application 등록에서 '지역 검색 결과 조회' 선택 → 키 ID/키 발급. 현재 한시적 무료이고 하루 25,000회 한도입니다(유료 전환 시 사전 공지 예정, 이후 요금은 확인되지 않음). 키 ID는 `NAVER_SEARCH_CLIENT_ID`, 키는 `NAVER_SEARCH_CLIENT_SECRET`에 넣습니다. 키는 채팅에 붙여 넣지 말고 봇의 비밀값 입력 카드로 넣으세요. 처음 시작 안내에서 이 단계를 함께 진행합니다.

**기존 사용자**: 이미 봇을 쓰고 있다면 템플릿을 다시 가져오지 말고 [업데이트 가이드](https://fnel-second.github.io/tesla-ready-korea/update.html)를 보세요.

- 필요 권한은 `vehicle_cmds`로, 공조 켜기와 같습니다. 추가 인증은 없습니다.
- 지오코딩은 네이버 클라우드 Maps의 같은 API 키를 씁니다(Geocoding 서비스 사용 신청 필요).
- 주차장 웹훅 퇴근 공조에는 해당하지 않습니다.
네이버 무료 한도: Directions 15는 월 3,000건입니다. 옛 호스트(naveropenapi)를 쓰면 401 오류가 납니다.

## 6. 애프터 블로우 (선택, 기본 꺼짐)

⚠️ 테슬라에는 공식 애프터 블로우 기능이 없습니다. 비슷한 효과를 내는 우회 방법입니다. 주차 후 잠깐 송풍해 에어컨 쪽 습기를 말리는 것이 목적입니다.

**흐름**
1. 신호 수신(`after_blow`) → 바로 켜지 않고 폰·채팅으로 "애프터 블로우 N분 뒤 시작 예정"을 알림 (N = 취소 대기 시간, 기본 20분)
2. 대기 상태와 시작 예정 시각을 상태 파일에 저장하고 N분 기다림. 그 사이 취소 신호가 오면 건너뜀
3. 시작 직전 Fleet API로 다시 확인: P단(`shift_state`)·주차 상태인지, 캠프·도그 모드가 꺼져 있는지(`climate_keeper_mode`가 `off`). 아니면 중단
4. `set_temps`를 바깥 온도와 비슷하거나 조금 높게 설정
5. `auto_conditioning_start`
6. 설정한 송풍 시간(5~10분) 뒤 `auto_conditioning_stop`. 송풍 중 기어가 P에서 벗어나면 즉시 정지
7. 설정 온도를 원래 값으로 되돌림

**동승자 보호**
- 신호는 운전자 폰 블루투스가 끊길 때 옵니다. 동승자가 차에 남아 있어도 실행될 수 있어 취소 대기 시간을 둡니다.
- API로는 차 안에 사람이 있는지 알 수 없습니다 (추측).
- `climate_keeper_mode`(캠프·도그 모드)는 API로 읽을 수 있습니다 (2026-10-17 확인).
- 취소 방법: 웹훅 본문 `after_blow_cancel`, 메일 제목 `[테슬라] after_blow_cancel`, 또는 채팅에 '취소'라고 답장.

| 취소 버튼 | 안드로이드 (Tesla Ready app 권장 · MacroDroid 대안) | 아이폰 (단축어) |
|---|---|---|
| 만들기 | **Tesla Ready app**: 애프터 블로우 신호를 보내면 20분짜리 취소 알림이 뜨고, 알림 버튼·위젯·바로가기로 `after_blow_cancel`을 보냄. 따로 만들 것 없음.<br>**MacroDroid**: 새 매크로: 트리거 `Shortcut Launched`(바로가기 실행) → 동작 `HTTP Request`(4절과 같은 값, 본문 `{"event":"after_blow_cancel"}`). 홈 화면 바로가기나 MacroDroid 위젯으로 꺼내 두고 취소할 때 누름. 메일이면 '이메일 보내기' 제목 `[테슬라] after_blow_cancel` | 새 단축어 'URL의 콘텐츠 가져오기' 본문 `after_blow_cancel`(또는 메일 제목 `[테슬라] after_blow_cancel`) → 홈 화면에 추가 또는 위젯 ¹ |

- 하루 횟수 제한은 없고 주행할 때마다 쓸 수 있습니다. 다만 중복 신호(예: 30분 안에 다시 온 신호)는 무시합니다.

**신호 보내는 방법 (4가지)**

| 항목 | 안드로이드 (MacroDroid) | 아이폰 (단축어 > 자동화 > 개인 자동화) |
|---|---|---|
| (앱) | **Tesla Ready app**: 앱 설정 '차량 블루투스'에서 차를 고르면 연결이 끊길 때 `{"event":"after_blow"}`를 보냄. 매크로 불필요 | — |
| 트리거 | 새 매크로: 트리거 `Bluetooth Event`(블루투스 이벤트) → `Device Disconnected`(기기 연결 끊김) → 차량 블루투스 기기 선택 | '블루투스 연결 해제'(차량 선택) 또는 'CarPlay 연결 해제' ¹, '즉시 실행' 켜고 '실행 시 알림' |
| 웹훅 | `HTTP Request` (4절과 같은 값), 본문 `{"event":"after_blow"}` | 'URL의 콘텐츠 가져오기' (4절과 같음), 본문 `after_blow` |
| 메일 | '이메일 보내기', 제목 `[테슬라] after_blow` | '메일 보내기', 제목 `[테슬라] after_blow`, 보내기 전 확인 끄기 ¹ |

¹ iOS 버전마다 이름이 다를 수 있음.
- 안드로이드는 차량 블루투스가 끊길 때 신호를 보내므로 어디에 주차하든 작동합니다. 주차장 매크로와 따로 만드세요.
- 메일 방식은 최대 5분 늦지만 애프터 블로우는 조금 늦어도 문제없습니다 (추측).

## 자주 나는 오류

| 증상 | 해결 |
|---|---|
| 401 / 403 | 헤더 `Authorization: Bearer <키>` 확인 |
| 404 | URL이 잘렸는지 확인하고 다시 복사 |
| HTTP 415 | Body 콘텐츠 유형을 `application/json`(또는 `text/plain`)으로 지정 |
| 응답 코드 0 | 폰 네트워크와 MacroDroid 권한 확인 |
| 안드로이드에서 주차장에 들어가도 신호가 안 감 | 매크로가 켜져 있는지, 위치 '항상 허용'·배터리 최적화 제외 확인, 반경 넓히기 |
| 안드로이드 신호가 두 번 감 | 같은 일을 하는 매크로가 두 개인지, Automate 흐름이 아직 돌고 있는지 확인하고 하나만 남기기 |
| 아이폰에서 도착해도 실행 안 됨 | 위치 서비스에서 단축어 '항상' 허용, 자동화의 '즉시 실행' 켜짐 확인, 도착 반경 넓히기 |
| 아이폰 메일이 자동 발송 안 됨 | '메일 보내기'의 보내기 전 확인 끄기, 안 되면 웹훅 방식 사용 |
| 깨우기 406 | 본문 `{}`와 Content-Type 추가 |
| 다른 주차장이 골라짐 | 이름에 목적지명이 든 주차장만 후보라, 일정 장소에 정확한 장소/건물 이름을 적기. 그래도 틀리면 채택 거리를 줄이거나 주차장 우선 목적지 끄기 |
| 내비 목적지가 안 뜸 | 지오코딩 결과(좌표) 확인 → 실패 시 share 주소 전송 결과 확인, 일정 장소를 정확한 주소로 수정 |
| 재부팅 뒤 실패 | 프록시 다시 띄우기 (스크립트에서 자동으로) |
| 블루투스가 다른 이유로 끊겨 애프터 블로우가 잘못 켜짐 | 대기 중 취소 버튼으로 취소. P단·주차 확인에서도 걸러짐. 자주 생기면 트리거 기기를 차량으로 한정하거나 CarPlay 해제로 바꾸기 |
| 애프터 블로우 뒤 온도가 그대로 | 원복 온도 설정 확인, 송풍 종료(`auto_conditioning_stop`) 실패 여부를 보고에서 확인 |

## 내 환경에 맞게 바꿀 값

| 항목 | 예시 / 설명 |
|---|---|
| 공조 설정 온도 | 예: 21°C 고정 (켤 때마다 이 온도로 설정) |
| 퇴근 요일과 시간대 | 예: 평일 17:30~23:00 |
| 주차장 위치(지오펜스) | 안드로이드: MacroDroid `Location Trigger` 구역·반경 / 아이폰: 단축어 '도착' 위치·반경 |
| 걸어서 차까지 가는 시간 | 예: 집 2분, 직장 15분 |
| 공조 미리 켜는 시간 | 예: 차 출발 10분 전 |
| 내비 목적지 자동 전송 | 켜기 / 끄기 (기본: 켜기, 일정 기반 준비에만 적용) |
| 주차장 우선 목적지 | 켜기 / 끄기, 채택 거리(예: 500m). 지역 검색 키 필요 |
| 캘린더 연결 | (권장) Google Calendar 등 |
| Tesla 앱 Client ID/Secret, 키 쌍 | 봇 컴퓨터에만 보관 |
| GitHub Pages 주소, 차량 | 본인 것 |
| 애프터 블로우 | 켜기 / 끄기 (기본: 끄기) |
| 애프터 블로우 송풍 시간 | 예: 5~10분 |
| 애프터 블로우 취소 대기 시간 | 기본: 20분 |
| 애프터 블로우 뒤 원복 온도 | 예: 평소 설정 온도(21°C) |
| 웹훅 URL과 키, 네이버 API 키 | 공개 금지 |

🔒 토큰, 키, 웹훅 URL은 절대 공개된 곳에 올리지 마세요.
