## 어떻게 동작하나요

```
[폰 MacroDroid] 주차장 진입
   → HTTP POST (웹훅)
   → [Grok Bot 루틴] 평일 퇴근 시간대인지, 오늘 이미 켰는지 확인
   → [작업용 컴퓨터] 토큰 갱신 → 명령 서명 프록시
   → [Tesla Fleet API] 차량 깨우기 → 공조 켜기 → 켜졌는지 확인
```

- 실제 기록: 신호를 보내고 1분 안에 공조가 켜졌습니다.
- 공조는 하루에 한 번만 켭니다. 정해 둔 시간대 밖이면 무시합니다.
- 공식 API만 씁니다 (Tessie, TeslaFi 같은 서드파티는 안 씀). 서드파티는 월 구독료가 있고 Tesla 계정 토큰을 외부 회사에 맡겨야 합니다. 공식 API를 쓰면 비용은 사실상 0원이고, 키와 토큰이 내 봇 컴퓨터에만 있습니다.

## 🔰 API가 처음이라면

난이도는 중상입니다. 다만 어려운 기술 작업 대부분은 Grok Bot이 자기 컴퓨터에서 대신 해 줍니다. 템플릿을 가져온 뒤 봇에게 "처음부터 같이 해 줘"라고 하면 됩니다.

**봇이 해 주는 일**
- 키 쌍(개인키·공개키) 만들기
- `tesla-http-proxy` 설치와 실행
- 토큰 갱신, 차량 깨우기, 공조 켜기 스크립트 만들기
- 파트너 등록 요청 보내기, 웹훅 루틴 만들기
- 테스트 결과 확인과 오류 원인 찾기

**내가 직접 해야 하는 일** (화면 클릭 위주)
1. GitHub 가입 → 새 저장소 `<아이디>.github.io` 만들기 → Pages 켜기
2. 봇이 준 공개키 파일을 저장소의 `.well-known/appspecific/` 폴더에 올리기 (봇이 파일과 경로를 알려 줌)
3. developer.tesla.com 로그인 → 앱 만들기 → 봇이 알려 주는 origin, 리디렉트 URL, 권한 입력
4. Client ID는 봇에게 알려 주고, Client Secret은 봇이 띄우는 비밀값 입력 카드에만 넣기 (채팅에 붙여 넣지 않기)
5. 봇이 준 인증 링크를 열어 Tesla 계정으로 승인
6. Tesla 앱이나 차량 화면에서 가상 키 승인
7. 결제 페이지에서 결제수단 확인
8. MacroDroid 매크로 만들기 (4번 항목대로)

막히면 그 화면을 캡처해서 봇에게 보내면 됩니다. 아래 1~3번은 봇이 무엇을 하는지 궁금한 분을 위한 상세 설명입니다.

## 1. Tesla Fleet API 앱 만들기

1. developer.tesla.com에서 앱을 만듭니다. 앱 이름에 `tesla`나 한글이 들어가면 거부됩니다.
2. EC 키 쌍을 만들고, 공개키를 GitHub Pages의 `/.well-known/appspecific/com.tesla.3p.public-key.pem`에 올립니다. 개인키는 작업용 컴퓨터에만 둡니다.
3. 허용 origin(`https://<아이디>.github.io`)과 리디렉트 URL(`.../callback`)을 등록합니다.
4. 파트너 계정을 등록합니다. 한국 차량도 NA 엔드포인트(`fleet-api.prd.na.vn.cloud.tesla.com`)를 씁니다.
5. OAuth 권한(scope): `openid offline_access vehicle_device_data vehicle_cmds vehicle_charging_cmds vehicle_location`
   vehicle_location을 빼먹으면 나중에 다시 인증해야 합니다.
6. 차량 화면이나 Tesla 앱에서 가상 키(서드파티 키)를 승인합니다.

💰 요금: 명령 1,000건당 $1, 데이터 500건당 $1, 깨우기 50건당 $1이고, 매달 $10 할인이 있습니다. 개인이 쓰는 양이면 사실상 0원입니다 (추정). 결제수단이 없으면 앱이 비활성화될 수 있으니 결제 페이지를 한 번 확인하세요.

## 2. 명령 서명 프록시와 스크립트

최신 테슬라는 서명된 명령만 받습니다.

- Tesla 공식 `vehicle-command`의 `tesla-http-proxy`를 `127.0.0.1:4443`에 띄웁니다.
- 스크립트가 하는 일은 다음 순서입니다.
  1. 프록시가 꺼져 있으면 띄웁니다 (재부팅 대비).
  2. refresh token으로 토큰을 갱신합니다.
  3. `wake_up`을 보냅니다. 본문 `{}`와 `Content-Type: application/json`이 꼭 있어야 합니다 (빈 본문이면 406).
  4. 차량이 online이 될 때까지 최대 약 1분 기다립니다.
  5. 프록시로 `auto_conditioning_start`를 보냅니다.
  6. `climate_state`로 켜졌는지 확인합니다.
- 상태 파일에 `last_on_date`를 남겨 하루 한 번만 켜지게 합니다.

## 4. MacroDroid 매크로

- 트리거: 위치(지오펜스), 주차장 구역 진입
- 동작: HTTP 요청
  - 메서드 `POST`, URL `<웹훅 URL>`
  - 헤더: 이름 `Authorization`, 값 `Bearer <웹훅 키>`
  - Body: 콘텐츠 유형 `text/plain`, 본문 `parking_enter`
  - ⚠️ 콘텐츠 유형을 안 정하면 415 오류가 납니다.
- 진단 팁: '응답'에서 HTTP 응답 코드를 지역 변수 `code`에 저장하고, 다음 동작으로 토스트 `{lv=code}`를 띄우면 결과 코드를 바로 볼 수 있습니다.
- (선택) 같은 매크로에서 메일도 보내 두면 백업 신호로 쓸 수 있습니다. 다만 메일 확인은 5분 간격이라 느립니다.

### 아이폰이라면 (단축어)

MacroDroid 대신 iOS 단축어 앱의 '개인용 자동화'를 씁니다 (직접 테스트해 보지는 않음).
- 트리거: '도착', 위치는 주차장
- 동작: 'URL의 콘텐츠 가져오기'
  - URL `<웹훅 URL>`, 방법 `POST`
  - 헤더: `Authorization` = `Bearer <웹훅 키>`, `Content-Type` = `text/plain`
  - 요청 본문: `parking_enter` (텍스트 형식을 지원하지 않으면 JSON으로 `event` = `parking_enter`)
- '즉시 실행'을 켜야 확인 없이 바로 실행됩니다. iOS 버전에 따라 위치 자동화가 알림을 눌러야 실행될 수도 있습니다 (추측).

### HTTP 요청이 어렵다면 (Gmail 방식)

웹훅 설정이 부담스러우면 메일로 신호를 보내는 방법도 있습니다. 대신 Grok Bot이 5분마다 메일을 확인하기 때문에 최대 5분 늦게 켜집니다.

1. MacroDroid 동작으로 HTTP 요청 대신 '이메일 보내기'를 넣습니다.
   - 받는 사람: 내 Gmail 주소
   - 제목: `[위치] parking_enter`
   - 아이폰은 단축어의 '메일 보내기'를 쓰면 되는데, 확인 없이 자동 발송이 안 될 수 있습니다 (추측).
2. Gmail에서 필터를 만듭니다. 보낸 사람이 내 주소이고 제목에 `[위치]`가 들어간 메일은 받은편지함을 건너뛰고 라벨 `위치`를 붙이게 합니다. 받은편지함이 지저분해지지 않습니다.
3. Grok Bot에 Gmail 커넥터를 연결합니다.
4. 봇에게 "퇴근 공조 메일 루틴 만들어 줘"라고 하면 됩니다. 평일 퇴근 시간대에 5분마다 제목이 `[위치] parking_enter`인 새 메일을 찾고, 있으면 공조를 켜는 루틴입니다. 처리한 메일은 기록해 두어 두 번 켜지지 않게 합니다.
5. 테스트는 같은 제목으로 메일을 직접 보내 보면 됩니다.

웹훅과 메일을 같이 써도 됩니다. 하루 한 번만 켜지게 되어 있어서 먼저 도착한 신호로 켜지고, 나머지는 무시됩니다.

## 5. 일정 기반 준비 (선택)

일정이 있는 날, 차의 실시간 위치에서 일정 장소까지의 소요시간을 네이버 Directions 15(`maps.apigw.ntruss.com`, `option=trafast`)로 구합니다.

- 차 출발 = 일정 시작 − 도착 후 여유 − 주행 시간
- 내가 출발 = 차 출발 − 걸어서 차까지 가는 시간
- 공조 켜기 = 차 출발 − 10분

출발 2시간, 1시간, 30분 전에 다시 계산해서, 길이 막히면 공조와 출발을 앞당깁니다.
네이버 무료 한도: Directions 15는 월 3,000건입니다. 옛 호스트(naveropenapi)를 쓰면 401 오류가 납니다.

## 자주 나는 오류

| 증상 | 해결 |
|---|---|
| HTTP 415 | Body 콘텐츠 유형을 `text/plain`이나 `application/json`으로 지정 |
| 401 / 403 | 헤더 `Authorization: Bearer <키>` 확인 |
| 404 | URL이 잘렸는지 확인하고 다시 복사 |
| 응답 코드 0 | 폰 네트워크와 MacroDroid 권한 확인 |
| 깨우기 406 | 본문 `{}`와 Content-Type 추가 |
| 재부팅 뒤 실패 | 프록시 다시 띄우기 (스크립트에서 자동으로) |
